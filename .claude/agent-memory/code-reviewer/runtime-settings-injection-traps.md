Reviewing anything that injects `RuntimeSettings` (#143 and follow-ups) — recurring traps:

- **Moving an env read from `web/auth.py::_get_env` to `config/runtime_settings.py` silently changes parsing.** `_get_env` strips and maps whitespace-only to `None` (so `or "true"` defaults apply); `_bool_env`/`os.environ.get` do not. At commit 4a717f9 `WEB_SECURE_COOKIES="true "` / `"   "` flipped the admin cookie's `Secure` flag from on to **off** — a security downgrade inside the commit that claimed to fix the opposite bug. Always diff the *helper*, not just the truthy tuple. `WEB_TRUST_FORWARDED_FOR` was fine (bare `os.environ.get` on both sides, tuple deliberately excludes `"on"`), despite a `rate_limit.py` docstring claiming it had "a narrower truthy set than the snapshot".
- **`tests/test_env_centralization.py`'s per-module pinned sets only see `os.getenv(...)`, `os.environ.get(...)`, `os.environ[...]` and calls to `_get_env`.** Inside a *pinned* module (e.g. `web/auth.py`), `if "X" in os.environ:`, `os.environ.pop("X")` and `os.environ.setdefault("X", ...)` are invisible to **both** `test_allowed_modules_read_exactly_the_pinned_variables` and `test_computed_env_reads_do_not_multiply` — verified by mutation. Non-pinned modules are still caught, because `_touches_environ` matches any `os.environ` attribute. `from os import getenv` evades everywhere (pre-existing).
- **`test_tenant_factory_eviction.py::TestProcessFactorySingleton` does not test singleton-ness.** It issues *one* request, so mutating `_tenant_service_factory` to rebuild `_FACTORY` on every call still passes. It *does* catch the original bug shape (shutdown reaching a different factory). To make it real it needs two requests plus an identity assert.
- **`RuntimeSettings(frozen=True)` is unhashable** because `publish_timeout_overrides` is a dict — `hash(settings)` raises `TypeError`, so a future `@lru_cache` keyed on settings fails at runtime, not import. `frozen=True` also does not stop `settings.publish_timeout_overrides[k] = v` (a fleet-wide write); the follow-up work wraps it in `MappingProxyType` via a field validator.
- `HOT_PATH_MODULES` in `test_runtime_settings_injection.py` now **does** include `web/settings.py` and `web/app.py` (with `ALLOWED_LOAD_SITES`). The guard matches the bare name `load_runtime_settings` only — `module.load_runtime_settings()` evades it, and a no-arg `get_runtime_settings()` (which falls back to a fresh parse) is not checked at all. No src caller passes no-arg today, yet `request` still defaults to `None`.
- **Process-wide singletons must not be `lru_cache`d on arguments.** `web/middleware.py::_tenant_service_factory(settings)` and the lifespan shutdown must reach the *same* object. Current shape: module-level `_FACTORY` + `_existing_tenant_service_factory()` + `reset_tenant_service_factory()`.
- **CONFIGURATION.md's "#143 When a change takes effect" paragraph** claims the per-request env reads are "exactly the variables `web/auth.py` reads". That matches auth.py's 12 names, but `utils/state.py` reads `XDG_CACHE_HOME` per posted-state load/save (publish path, no-DB mode) and `web/app.py:365` `/health/ready` reads `DATABASE_URL` per request.
- **Counting the env allow-list for the AC** ("≤12 sites in 5 modules"): count `os.environ`/`os.getenv` AST nodes under `publisher_v2/src/publisher_v2`, excluding `config/**`, `web/auth.py` and `tools/migrate_storage.py` (9 sites, left alone by the spec).
- **Verifying "these tests failed first"**: `git worktree add --detach <scratch> <commit>^`, then `git checkout <commit> -- <test files>` inside it, and run with the main repo's `.venv/bin/python -m pytest` from the worktree root. Remove the worktrees afterwards. See also [[mutation-check-review-technique]] and [[layering-guard-review-traps]].
- **Check `git status` before and after running gates.** During this review the main working tree gained uncommitted follow-up edits to `runtime_settings.py`/`web/app.py`/`web/middleware.py` mid-run, which produced a phantom 6-failure suite result. Run gates in a detached worktree at the exact commit under review.
